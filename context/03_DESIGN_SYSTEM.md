# PROXI — Design System

## Purpose

This document defines the official visual design system for Proxi.

Every interface, component, layout, interaction, and screen must follow the standards defined here.

The objective is to ensure that every part of Proxi feels like it belongs to the same product regardless of who designs or develops it.

Consistency is more important than creativity.

When uncertainty exists, always prioritize consistency with the existing design system over introducing something new.

---

# Design Philosophy

Proxi is not simply a marketplace.

It is a technology platform built around one core emotion:

**Trust.**

Every design decision should increase user confidence.

The interface should communicate:

- Professionalism
- Reliability
- Simplicity
- Transparency
- Human connection

The design should feel modern enough to compete with global technology companies while remaining approachable for users of all technical skill levels.

Users should immediately understand:

- what Proxi does,
- who it is for,
- what action to take next.

The interface should never require users to "figure things out."

---

Every screen should feel:

- Clean

- WordPress templates

- Government portals

# Core Design Principles

Every design decision should satisfy these principles.

## 1. Trust First

Trust is Proxi's strongest competitive advantage.

Every screen should reinforce trust through:

- clarity
- transparency
- consistency
- professionalism

---

## 2. Simplicity

Every screen should have one obvious next action.

Avoid unnecessary options.

Reduce decision fatigue.

---

## 3. Clarity

Information hierarchy should always be obvious.

Users should instantly know:

- what they're looking at,
- why it matters,
- what happens next.

---

## 4. Consistency

The same interaction should behave the same way everywhere.

Buttons

Cards

Inputs

Icons

Animations

Spacing

Typography

should remain consistent throughout the product.

---

## 5. Accessibility

Beautiful interfaces that exclude users are unacceptable.

Accessibility is a requirement, not a feature.

---

## 6. Performance

The design system should encourage lightweight interfaces.

Avoid unnecessary visual effects that increase loading time.

---

## 7. Mobile First

Every feature should be designed for mobile before desktop.

Desktop layouts are adaptations—not separate products.

# Responsive Design Philosophy

Proxi follows a **Mobile-First Responsive Design Strategy**.

The majority of early users are expected to access Proxi using smartphones.

Every page should therefore be designed for mobile first before being expanded for larger screens.

Desktop layouts should never be created by simply enlarging the mobile interface.

Instead, desktop should intelligently use additional space while preserving the same user journey.

---

# Responsive Principles

Every responsive layout should:

- Preserve branding
- Preserve hierarchy
- Preserve functionality
- Preserve user flow

Only the layout changes.

The experience should remain familiar across every device.

---

# Mobile Philosophy

Mobile is the primary experience.

Characteristics:

- Single-column layouts
- Large touch targets
- Simple navigation
- Short forms
- Large buttons
- Minimal scrolling where possible

Every interaction should be thumb-friendly.

---

# Tablet Philosophy

Tablet layouts bridge mobile and desktop.

Characteristics:

- Increased spacing
- Larger cards
- Two-column layouts where appropriate
- Better content distribution

Tablet should not simply stretch mobile.

---

# Desktop Philosophy

Desktop should feel intentionally designed.

Desktop should:

- Reduce scrolling
- Use multiple columns
- Increase whitespace
- Improve hierarchy
- Display more contextual information

Desktop is not an enlarged mobile application.

Desktop is an optimized desktop experience.

---

# Screen Consistency

Every screen should exist in two official layouts:

- Mobile
- Desktop

Both layouts should communicate the same information.

Only layout, spacing, and positioning should change.

Branding, content, interactions, and visual identity must remain consistent.

Avoid ALL CAPS except for small labels.

Headings should remain concise.

# AI Implementation Rules

When creating UI components:

- Reuse existing components before creating new ones.
- Never introduce new button styles without approval.
- Never create additional card designs unless required by a new feature.
- Maintain consistent spacing, typography, and corner radius.
- Follow the approved color palette exactly.
- Use the official SVG assets whenever available.
- Generate responsive versions of every component.
- Ensure components work equally well on mobile and desktop.
- Components must be reusable, accessible, and scalable.
- Optimize for readability before visual complexity.

# Mobile & Desktop Layout Rules

Every screen in Proxi must have both a mobile and desktop layout.

The mobile version is the primary design reference.

Desktop should adapt the layout, not simply enlarge the mobile design.

## Mobile

- Single-column layouts.
- Bottom navigation where appropriate.
- Full-width cards.
- Thumb-friendly interactions.
- Large touch targets.
- Optimized for one-handed use.

## Desktop

- Multi-column layouts where beneficial.
- Top navigation.
- Better use of horizontal space.
- Reduce unnecessary scrolling.
- Increase whitespace.
- Preserve the same user journey as mobile.

Both versions must remain visually and functionally consistent.

# Accessibility

Every interface must:

- Meet WCAG AA contrast requirements.
- Support keyboard navigation.
- Include visible focus states.
- Use semantic HTML.
- Include accessible labels.
- Never rely on color alone to communicate meaning.
- Maintain minimum touch targets of 44px.

Accessibility is a requirement, not an enhancement.

---

# Animations

- Fade
- Slide

Avoid decorative animations.

Never sacrifice performance for visual effects.
