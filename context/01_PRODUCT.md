# PROXI — Product Specification

## Product Overview

Proxi is a two-sided marketplace that connects customers with trusted, verified artisans and skilled professionals.

The platform enables customers to easily discover, compare, book, communicate with, and securely pay professionals for local services.

For professionals, Proxi provides a platform to showcase their skills, build a trusted reputation, receive nearby job requests, and grow their business.

The first release focuses on Benin City, Nigeria, with future expansion to other cities.

---

# Product Type

Marketplace Platform

Category:

Local Services Marketplace

Comparable Products:

- Uber (simplicity)
- Airbnb (trust)
- TaskRabbit (marketplace)
- Thumbtack (service discovery)
- Urban Company (home services)

Proxi should learn from these products but maintain its own identity.

# Primary Goals

For Customers

- Find trusted professionals quickly.
- Reduce the stress of hiring artisans.
- Increase confidence before booking.
- Make booking simple.
- Ensure transparent pricing.
- Enable secure payments.
- Provide a professional hiring experience.

For Professionals

- Receive consistent job opportunities.
- Build a strong reputation.
- Increase visibility.
- Manage bookings efficiently.
- Grow a sustainable business.

# User Types

Customers use Proxi to:

- Browse categories
- Compare professionals
- Read reviews

## Professional

Professionals use Proxi to:

- Create professional profiles
- Verify their identity
- Receive job notifications
- Accept or decline jobs
- Manage bookings
- Chat with customers
- Build ratings
- Track earnings
- Manage availability

---

# Marketplace Model

Proxi does not employ artisans.

Professionals remain independent service providers.

Proxi acts as a trusted platform that facilitates discovery, booking, communication, and secure transactions.

# Customer Journey

1. Open Proxi
2. Search or browse services
3. Select a category
4. Compare professionals
5. View a professional's profile
6. Book an appointment
7. Receive confirmation
8. Chat if needed
9. Pay securely
10. Job completed
11. Leave a review

---

# Professional Journey

1. Register
2. Complete verification
3. Create profile
4. Set service categories
5. Set service area
6. Receive nearby requests
7. Accept booking
8. Complete service
9. Receive payment
10. Build reputation

- Profile photo
- Portfolio images
- Ratings
- Reviews

- Completed jobs

# MVP Scope

The first production release should focus on solving one problem well:

Helping customers discover and hire trusted professionals nearby.

Everything included in the MVP should directly support this goal.

---

# Out of Scope (Initial Release)

The following features are intentionally excluded from the first release unless explicitly approved:

- AI recommendations
- Voice assistant
- Loyalty programs
- Referral rewards
- Multi-language support
- International expansion
- Advanced analytics dashboards
- Team management
- Franchise management
- Enterprise accounts
- Subscription plans
- Video consultations
- Live location tracking
- In-app insurance products

These features may be considered after the core marketplace has been validated.

# Waitlist Objectives

The waitlist is the first public version of Proxi.

Its objectives are:

- Introduce the Proxi brand.
- Clearly explain the problem being solved.
- Build trust.
- Validate market demand.
- Collect early customers.
- Collect early professionals.
- Measure interest across service categories.
- Build an engaged launch community.

The waitlist should feel like a polished product, not a temporary landing page.

---

# Product Principles

Every screen should answer one question:

"What is the next easiest action for the user?"

Avoid unnecessary complexity.

Reduce cognitive load.

Prioritize clarity over decoration.

Every interaction should move users closer to their goal.

---

# AI Instructions

When implementing features:

- Stay within the approved product scope.
- Do not invent new marketplace features unless requested.
- Prefer simplicity over feature quantity.
- Reuse existing UI patterns and components.
- Preserve consistency across customer and professional experiences.
- Every new feature must support trust, transparency, or simplicity.
- If a requested feature conflicts with the product vision or MVP scope, explain the trade-offs before implementing it.
